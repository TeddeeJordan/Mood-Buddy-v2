# Mood Buddy v2

Expo SDK 57 / React Native 0.86 / React 19.2 / TypeScript 6 (strict). iOS and Android phones only (no web, no tablet). Light theme only.

- Read `AGENTS.md` first (Expo version rules, commands, CNG rules).
- The product spec is `docs/SPEC.md`. Its decisions (D1–D50) are settled; don't reopen them in code.

## Commands

```bash
npx expo install <pkg>     # the only way to add dependencies (yarn.lock project; never npm/pnpm/bun lockfiles)
yarn lint                  # expo lint src plugins
yarn typecheck             # tsc --noEmit (includes plugins/**/*.js)
yarn test                  # jest
yarn test:coverage         # jest --coverage (enforces thresholds)
yarn test:tz               # whole suite in Asia/Kolkata and America/Los_Angeles
yarn run check             # lint + typecheck + test:coverage + test:tz — the done-gate (`run` is required: bare `yarn check` is Yarn 1's built-in lockfile check)
npx expo-doctor
```

Typed routes: `.expo/types/router.d.ts` is git-ignored and generated by Expo CLI when the dev server starts (`npx expo start`). On a clean checkout `tsc` still passes without it (Href falls back to a loose type), but run `npx expo start` once to get typed `Href` checking.

## Conventions

These are the rules the reviewer agent checks against. They adapt the architect agent's defaults per SPEC §6.3.

### Stack and builds
- Expo Router, Hermes, New Architecture, TypeScript strict. No `any` without a written reason.
- **Development builds only; Expo Go is not a target** (MMKV/Nitro are not in Expo Go). Profiles in `eas.json`.
- **CNG:** never create or edit `ios/` or `android/` by hand (both git-ignored). Native config goes through `app.json` and config plugins. Static `app.json`, no `app.config.ts`. Local native code lives in local Expo modules under `modules/` (autolinked); today only `modules/no-backup` (iOS, D49). Local config plugins live in `plugins/` (CommonJS, imported from `expo/config-plugins`) and are listed in `app.json` `plugins`; today `plugins/withAndroidFontScaleConfigChange.js` adds `fontScale` to MainActivity's `configChanges` so a system font-size change doesn't recreate the activity and drop in-memory drafts. Keep it: RN's native in-place re-layout is incomplete on its own, so the JS font-scale re-layout pass (Theme and accessibility → Live text-size changes) completes it. Don't add `density` without device testing. Changing a plugin needs `npx expo prebuild --clean` and a native rebuild. `plugins/` is in the done-gate: `yarn lint` lints `src plugins`, and `tsconfig.json` includes `plugins/**/*.js`; every plugin file starts with `// @ts-check` (the base config has `allowJs` but no global `checkJs`, so a file without it is not type-checked) and types its exports with JSDoc.
- Owner-chosen libraries that override AGENTS.md's "prefer Expo modules" (SPEC §6.3, §7.3): `react-native-mmkv`, Redux Toolkit, TanStack Query, Axios, FlashList. Don't swap any of them without owner sign-off.
- No legacy-architecture-only libraries. Check maintenance and New Architecture support before adding a package.

### Folders
- **Routes live in `src/app/` (D38).** This deliberately deviates from the architect default of a root `app/` folder; don't flag it. Route files stay thin: re-export a screen from `src/ui/screens/` plus route-level options only.
- `src/constants`, `hooks`, `services`, `state`, `themes`, `types`, `utils`, `ui/{components,screens,widgets}`, `tests/{__tests__,__mocks__,helpers}`. No `managers/` (no analytics).
- One PascalCase folder per component/screen/widget: `Name.tsx` (view), `Name.props.ts` (prop types + `StyleSheet.create`, theme-dependent styles via `makeStyles(theme)`), `useName.ts` (logic; omit when there is none).
- No inline style objects in components. Navigator option objects in layout routes (e.g. `tabBarStyle`) are the one exception.

### Navigation (D35)
- Root Stack (`unstable_settings.anchor = '(drawer)'`) → Drawer → JS Tabs. Chat is a root Stack screen (`src/app/chat.tsx`), not a tab or drawer screen.
- **Import `Tabs` only from `expo-router/js-tabs`.** Never `NativeTabs` (hidden native tabs can't be navigated to), never `Tabs` from `expo-router` (deprecated). ESLint enforces this (`no-restricted-imports` / `no-restricted-syntax` in `eslint.config.js`).
- **No direct `@react-navigation/*` imports** (ESLint-enforced). Use `expo-router/drawer` (Drawer, `DrawerContentScrollView`, `DrawerContentComponentProps`) and `expo-router/react-navigation` (`DrawerActions`, `PlatformPressable`, …).
- **`HapticTabButton` goes only in Tabs `screenOptions.tabBarButton`, never in a screen's own options** (`href` + `tabBarButton` on one screen throws).
- **Hidden tabs (Diary, Profile, Settings) use the object form `options={{ href: null }}`**; a function-form `options` ignores `href`.
- Drawer menu = Diary, Profile, Settings only. Active item comes from `usePathname()`. Don't set `backBehavior` (default `firstRoute` gives Android back → Home → exit).
- Route params and deep links are untrusted. Chat accepts no prompt text from a URL; validate any param before use.

### State placement
1. Local state in the component hook (default) → 2. lifted to the screen hook → 3. React Context for rarely changing subtree values → 4. Redux slice only for cross-screen, navigation-surviving or persisted state → 5. server/local-DB data never in Redux (TanStack Query).
- Redux has one slice today: `settings` (theme, AI toggle, `ai_chat_prompt_shown`, reminder enabled/hour/minute — persisted to MMKV by `src/state/persistSettings.ts` — plus memory-only `hasApiKey`). A `chat` slice is planned (SPEC §3.10). Add slices to `rootReducer` in `src/state/store.ts`.
- Use `useAppDispatch` / `useAppSelector` from `src/state/hooks.ts`. Keep selectors pure (React Compiler is on).
- Entries, prompts and profile live in SQLite and are read through TanStack Query keys in `src/services/query/queryKeys.ts`; invalidate the key family after writes.
- **Repositories** (`src/services/db/*Repository.ts`) are factories `createXRepository(db: SqlDatabase)`. `SqlDatabase` (`src/types/db.ts`) is a structural subset of expo-sqlite's `SQLiteDatabase` (`runAsync`, `getAllAsync`, `getFirstAsync`, `withTransactionAsync`) so `NodeSqliteAdapter` satisfies it in tests. Bind every parameter; no SQL built from user values. Validate score columns with `isScaleValue` in row mappers instead of casting. Screens get repositories through `src/hooks/useRepositories.ts` (`useEntriesRepository`, `useProfileRepository`: `useSQLiteContext` + `useMemo`), which is also the seam screen tests mock.
- **Write mutations** live in `src/hooks/use*Mutation.ts`. Cache invalidation (and any other side effect that must not be lost, e.g. the future reminder cancel) goes in the hook-level `useMutation` `onSuccess`, never in per-call `mutate(vars, { onSuccess })` callbacks, which TanStack Query skips if the caller unmounted. Screens use `mutateAsync` + try/catch for UI-only follow-up (reset form, Snackbar) and disable the trigger while `isPending`, and guard re-entry with a ref (disabled alone doesn't stop a double tap). A fast local save can finish before the second tap of a double tap lands, so Home also ignores a Submit on the untouched, just-reset form for `RESUBMIT_GUARD_MS` after a successful save, and Profile ignores Edit (which takes Save's place in the header) for `EDIT_AFTER_SAVE_GUARD_MS` (`src/constants/limits.ts`). A new submit attempt (blocked or failed) hides the previous "Saved!" Snackbar and a blocked one scrolls to the first row with an error.
- Check-in: the entry and its diary prompt are inserted in one `withTransactionAsync` by `insertEntryWithPrompt`, which also runs the 90-day prompt purge (D3). Pure logic stays in `src/utils/` (`checkIn.ts` `buildNewEntry`, `diaryPrompt.ts`, `postCheckIn.ts` `decidePostCheckIn`). Note contents are user data: never log them or put them in error messages.
- **Profile photo (B11, D49):** `profile.photo_uri` stores only a **file name** inside `PROFILE_PHOTO_DIR` under the document directory, never a URI or absolute path (the iOS container path changes across app updates). All file work goes through `src/services/storage/profilePhotoStorage.ts`. A picked photo stays at the picker's cache URI as a draft and is **copied on Save** under a new unique name (so expo-image never shows a stale cache); if the DB write fails the new copy is deleted, and after a successful save every other file in the directory is swept. Delete-all uses `resetProfile()` + `deleteAllProfilePhotos()`. Bio and photo are never exported (D14, D34). The picker needs no permission (system photo picker, ADR 011): don't call `requestMediaLibraryPermissionsAsync` and keep `photosPermission`/`cameraPermission`/`microphonePermission: false` in the expo-image-picker plugin. Pass `exif: false`, but know it only stops EXIF being returned to JS: it does **not** strip metadata from the saved file (GPS tags may be copied into the output on iOS and Android). Accepted as low risk because the copy is local, excluded from backups and never exported; stripping would need expo-image-manipulator, which the owner ruled out (ADR 011). If Save finds the picker's cache file gone, `persistPickedPhoto` throws `PickedPhotoUnavailableError` (no user data) and the screen drops the draft photo and shows/announces "That photo is no longer available. Please pick it again.".
- **Unsaved drafts (leave confirmation):** a screen with an edit mode registers `useLeaveGuard(guard, onBlur)` (`src/hooks/useLeaveGuard.ts`). JS Tabs keep screens mounted, so `beforeRemove`/`usePreventRemove` don't fire on tab or drawer switches; instead the Tabs `screenListeners` (`useTabLeaveGuardListeners`), the drawer items (`useRequestLeave`) and Android hardware back ask the focused screen's guard (one `LeaveGuardProvider` around the Drawer). With unsaved changes the guard shows a "Discard changes?" dialog (Keep editing / Discard, 48dp buttons) and navigates only on Discard; an unchanged edit, or any other blur (deep link, notification), drops the draft and returns to view mode. **Pushing a screen onto the root Stack (e.g. Chat) is such a blur: it silently drops the draft unless that entry point calls `requestLeave` first.** New navigation entry points must call `requestLeave(go)` before navigating. On Android, hardware back while the drawer is open is left to the navigator (it closes the drawer) and the guard is not asked (`isInsideOpenDrawer`).
- Single-consumer MMKV keys (`reminder_tz`, `tz_change_detected_at`, `quote_cache`, `install_initialized`) are read/written only through `src/services/storage/settingsStorage.ts`.

### Storage and security
- **`hasApiKey` is never persisted. The API key lives only in SecureStore** (`src/services/storage/secureKeyStore.ts`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`). Never put it in Redux, MMKV, logs, error messages or analytics. Only the Anthropic service may call `readApiKey()` (ESLint blocks importing it outside `src/services/anthropic/**` and tests).
- First-run cleanup (`runFirstInstallCleanup`) runs before `hasApiKey` is derived.
- MMKV (`src/services/storage/mmkv.ts`, one instance) for non-secret settings only. No AsyncStorage.
- **Picker cache copies are deleted** once no longer needed (saved, replaced, removed, discarded) via `deletePickedPhotoCache`, and the whole `<cache>/ImagePicker/` folder is swept with `sweepPickerCache(keep)` (`src/services/storage/profilePhotoStorage.ts`) after Save, Cancel, Discard, leaving/blur, a replace, a remove, a cancelled or failed pick, a Save that fails because the picked photo is unavailable, and on entering edit mode: every file directly in it except the picked draft still in use (`keep`, or `null` for none) is deleted, because Android's picker also leaves an untracked pre-crop source copy per pick. Both are best-effort, never throw, never log, and only touch picker-named files directly in that folder (never subfolders, other cache folders or `profile/`). The kept draft is matched by file name (last path segment), not full path, so a `/private/var` vs `/var` or encoding difference can't delete it. **`sweepPickerCache` owns the whole `<cache>/ImagePicker/` folder app-wide:** a future picker feature (e.g. chat attachments) must coordinate with it, or its files are swept. Never sweep while the picker is open (`pickerOpen` ref): `pickPhoto` sweeps when it resolves. While the picker is open (until its result is processed; on iOS the picker closes before that) Save, Cancel, the avatar and Remove photo are disabled and their handlers return early (`isPickerOpen` state mirrors the ref for rendering). A pick that resolves after the screen unmounted is swept, never applied. A pick that resolves after its edit session ended (blur/deep link while the picker was open; tracked by the `editSession` ref) is discarded and swept, never applied.
- **No OS backups (D49, ADR 006).** Every persistent data location must stay out of backups. Keep SQLite and MMKV on their library-default directories: never pass `directory` to `SQLiteProvider`/`openDatabase*` or `path` to `createMMKV` (a test checks). New persistent files go in the document directory; temporary files (e.g. export CSVs) in the cache directory (`src/constants/dataLocations.ts`). Anything else needs the iOS exclusion list in `modules/no-backup/ios/BackupExclusion.swift` and `IOS_BACKUP_EXCLUDED_DIRECTORIES` updated together. Don't store user data in UserDefaults or Android SharedPreferences. Keep `android.allowBackup: false` and expo-secure-store's `configureAndroidBackup: true`.
- **No Face ID string (D50):** `faceIDPermission: false` in the expo-secure-store plugin; adding biometrics or `requireAuthentication` needs an owner decision first.
- **SQLite: every connection runs `PRAGMA foreign_keys = ON` first, outside any transaction** (`configureConnection` in `src/services/db/migrations.ts`). `SQLiteProvider`'s `onInit` (`migrateDbIfNeeded`, module scope for a stable identity) does this, then `user_version` migrations, each in its own transaction.
- **Don't use `withExclusiveTransactionAsync` for writes that rely on `ON DELETE CASCADE`:** it opens a separate connection and begins the transaction before your task runs, so foreign keys are off there. Use `withTransactionAsync`.
- New schema versions: append to `MIGRATIONS` and bump `SCHEMA_VERSION` in `src/constants/database.ts`.
- HTTPS only. Env holds public `EXPO_PUBLIC_*` values only (bundled and public); no secrets in env or source. Read env once in `src/constants/env.ts`; its validation must fail loudly with a clear message when a required value is missing (e.g. no `.env`), so a build never runs silently without config.
- **Every `.env*` file is git-ignored (`.env`, `.env.local`, `.env.development`, `.env.production`, `.env.test` …); only `.env.example` is committed** (`.gitignore`: `.env*` + `!.env.example`). `.env.example` holds placeholders / documented public defaults (added with the Axios feature). Each developer copies `.env.example` to `.env`. EAS builds get their values from EAS environment variables (`eas.json` / EAS dashboard), not a committed `.env`.
- Run `yarn audit` before release; fix moderate+ or record why not. Record exceptions in an ADR under `docs/adr/` (currently `007-dependency-audit-exceptions.md`; update it rather than adding a new one while it is current) plus a line under the CHANGELOG `### Security` heading.

### Dates (D20, D46)
- **An entry's day = its UTC `timestamp` + its own stored `tz_offset_min`**, never the device's current zone. Use `src/utils/dates.ts` (`localDateKeyFromUtc`, `utcSearchWindowForLocalRange` + exact filter). In SQL: `date(timestamp, tz_offset_min || ' minutes')`.
- "Today" is the device's current local date. Entries dated after today count as today for buckets/streak/reminder skip (`clampToToday`); Diary/export upper bound is `upperBoundKey`.
- `tz_offset_min` comes from `currentTzOffsetMin()` (minutes east of UTC, never −0).

### Scales (D39, D48)
- Scale constants in `src/constants/scales.ts` stay in **value order (1 → 5)** for every metric. Mood: 1 = worst … 5 = best. Stress/anxiety: 1 = least … 5 = most.
- Stress and anxiety render **5 → 1** left to right. That is a rendering rule only: use `displayOptions(scale)`; never reorder or reverse stored values.
- Note fields are evaluated on the **stored value** (`requiresNotes`, ≥ 4), never on tile position.
- Tile accessibility labels are **word-only** (`tileAccessibilityLabel`: "{Label}, {direction}" from the per-metric ladder). No numbers in labels.

### Theme and accessibility
- Paper MD3 light themes built by `buildPaperTheme(name)` in `src/themes/`; read with `useAppTheme()`. Three palettes: lavender (default), sage, water.
- **Contrast option C:** owner identity colours are containers/fills with dark text (`onPrimaryContainer` etc.); `primary`/`secondary`/`tertiary` are the ≥ 4.5:1 text variants; graphics and chart bars use the ≥ 3:1 `*Ui` / `stressBar` / `anxietyBar` tokens. `surfaceVariant` and `elevation.level1–5` are per-palette tints never darker than `background` (`level0` stays transparent). `src/tests/__tests__/themes/contrast.test.ts` asserts every text token (`on*`, `primary`, `secondary`, `tertiary`, `error`, metric text) ≥ 4.5:1 and every UI token (`outline`, `*Ui`, chart bars) ≥ 3:1 on `background`, `surface`, `surfaceVariant` and each opaque elevation level, plus each `on*`/container pair and the inverse (Snackbar) pair. Not asserted: disabled colours (exempt), `outlineVariant` (decorative dividers only), `backdrop`/`shadow`/`scrim`. Add new tokens there.
- **Screen-reader announcements:** dynamic messages that appear without focus moving (validation, save errors) are announced with `AccessibilityInfo.announceForAccessibility` on **both** platforms. The one iOS-only case is a message already surfaced through an Android live region, e.g. a Paper Snackbar (its live region is Android-only): announce it on iOS only, so TalkBack doesn't hear it twice. Use `announceForAccessibilityWithOptions(message, { queue: true })` for that iOS-only announcement (e.g. Home's "Saved!") when VoiceOver is about to re-read the focused control, so it isn't cut off.
- Icon buttons need an `accessibilityLabel`; selectable items expose `accessibilityState`: `selected` for tabs/list items, `checked` for radio/checkbox roles (EmojiTile uses role radio + checked).
- **Minimum touch target ≥ 44pt iOS / 48dp Android** (`MIN_TOUCH_TARGET = 48` in `src/constants/touchTarget.ts` covers both). Paper `IconButton` / `Appbar.Action` / `Appbar.BackAction` must take `ICON_BUTTON_TOUCH_TARGET` as their `style` (a `StyleSheet.create` entry in the component's `.props.ts`, as in `ScreenHeader`): their container has `overflow: 'hidden'`, which clips `hitSlop`, so `hitSlop` cannot enlarge the target. Re-check `ICON_BUTTON_TOUCH_TARGET` when react-native-paper is upgraded.
- **Text scaling (WCAG 1.4.4):** capping `maxFontSizeMultiplier` below 2.0 is allowed only when recorded in an ADR (today: the emoji tiles only, ADR 010; the header title is no longer capped). Text containers use `minHeight`, not `height`, and may wrap. Paper renders a string `Appbar.Content` title and every `Button` label on one line: `ScreenHeader` renders an uncapped, wrapping `Text` title; **every `Button` with a text label** (any `mode`: text, outlined, contained; dialog actions included) gets `maxWidth: '100%'` and a `flexShrink: 1` `labelStyle`, and a row of buttons (e.g. `Dialog.Actions`) gets `flexWrap: 'wrap'` so they stack instead of clipping. `flexShrink` shrinks a label, it doesn't wrap it: a single `Button` label can still ellipsize at extreme text sizes; only rows of buttons (`Dialog.Actions`) stack.
- **`ScreenHeader` is not Paper's `Appbar.Header`.** It copies Paper 5.15.3's MD3 header layout with plain views (safe-area top padding, larger side inset on both sides, row with `paddingHorizontal: 4` and `minHeight: HEADER_MIN_HEIGHT` (64), iOS centred title with a 52 trailing spacer when there are no actions, Android left-aligned title with a 12 start margin after the back action) and still uses `Appbar.Action` / `Appbar.BackAction` for the buttons. Reason: Paper's bar is a `Surface`, and on iOS `Surface` moves `height` to an outer view and gives the inner view `flex: 1` whenever any `height` is set (Paper always sets one), so the bar stays at its minimum and a large title is clipped. Don't go back to `Appbar.Header`/`Appbar` or give the bar a `height`; re-check the copied layout values when react-native-paper is upgraded.
- **No floating labels on text inputs.** Paper positions the outlined/flat `TextInput` label with fixed font-size constants, so at large text sizes it is clipped and overlaps the outline. Put a visible Paper `Text` label above the field (hidden from screen readers with `accessibilityElementsHidden` + `importantForAccessibility="no-hide-descendants"`) and give the input the same text as its `accessibilityLabel` (e.g. Profile's Bio, `BIO_LABEL`). Placeholder-only inputs (Home's NoteField) are fine.
- **Library default caps count as caps.** react-native-paper 5.15.3 `HelperText` and `TextInput` default `maxFontSizeMultiplier` to 1.5. Every `HelperText`/`TextInput` passes `maxFontSizeMultiplier={UNCAPPED_FONT_SCALE}` (`src/constants/textScaling.ts`, value `0`). Uncap with `0`, **never `undefined`** (that falls back to the default). The same applies to `Checkbox.Item` `labelMaxFontSizeMultiplier` and `Menu.Item` `titleMaxFontSizeMultiplier` (default 1.5; pass `UNCAPPED_FONT_SCALE`), and Paper `BottomNavigation` caps its labels at 1 by default (not used; the tabs are expo-router JS tabs). ESLint enforces the attribute for HelperText/TextInput/Checkbox.Item/Menu.Item and rejects `={undefined}` for these props (`no-restricted-syntax` in `eslint.config.js`). On every react-native-paper upgrade, grep its source for `maxFontSizeMultiplier =` defaults and update this rule.
- **Live text-size changes:** RN 0.86 re-measures text natively when the system scale changes while the app runs, but React's next commit reuses its own shadow nodes laid out at the old scale (clipped or oversized boxes). `useFontScaleRelayoutPass` (`src/hooks/`) watches `useWindowDimensions().fontScale` and returns a pass number (once on the change, once more after `FONT_SCALE_RELAYOUT_DELAY_MS`); `usePaperTheme` feeds it to `withTextRelayoutPass` (`src/themes/paperTheme.ts`), which toggles an invisible `fontStyle: 'normal'` on every Paper font so every Paper text node gets a changed prop and re-measures. **Nothing is remounted** (drafts, focus and scroll survive); never key-remount screens or providers on the font scale. Text Paper doesn't render must carry the marker itself (today the JS tab labels: `tabBarLabelStyle: textRelayoutStyle(theme)`); render app text with Paper components so it is covered. Don't put a theme font *after* an explicit `fontStyle` in a style array. Limit: Android emits the JS event only on resume (`DeviceInfoModule.onHostResume`, i.e. returning from Settings); a scale changed while the app stays in the foreground (e.g. `adb shell settings put system font_scale`) reaches JS on the next resume, and until then text boxes can stay clipped (text grew) or oversized (text shrank).
- **Selected state is never colour-only (WCAG 1.4.1):** tabs and drawer items swap to a filled icon when selected (outline otherwise); the active drawer item also gets a `primaryUi` (≥ 3:1) border because its `secondaryContainer` pill is < 3:1 on white.
- **Tab icons use `TabBarIcon`** (`src/ui/widgets/TabBarIcon/`) in `tabBarIcon`. The JS tab bar always renders two icon layers (active and inactive) and switches them by opacity only, so a plain icon leaves both variants in the accessibility tree. `TabBarIcon` reads the tab's real selected state from `TabSelectedContext` (provided by `HapticTabButton` from the button's `aria-selected`) and renders only the visible layer.
- Visible tabs set `tabBarAccessibilityLabel` via `tabAccessibilityLabel()` (`src/utils/tabAccessibility.ts`) so the position counts visible tabs only ("Home, tab, 1 of 2" on iOS; "Home, 1 of 2" on Android, where TalkBack announces the tab role itself).
- **Keyboard (forms):** `KeyboardAvoidingView` with `behavior="padding"` on **both** platforms. Android is edge-to-edge, so the window no longer resizes for the keyboard (`adjustResize` does nothing) and `undefined` leaves fields behind it. Screens start at the window top (no navigator header), so no `keyboardVerticalOffset`; Tabs set `tabBarHideOnKeyboard` on Android and the view re-measures, so there is no gap or double offset. Scroll the focused field into view with `src/hooks/useScrollIntoView.ts`. `react-native-keyboard-controller` needs owner sign-off.
- `SPLASH_BACKGROUND` in `src/themes/palettes.ts` must equal the splash `backgroundColor` in `app.json` (a test checks).

### Startup
- `SplashScreen.preventAutoHideAsync()` at module scope in `src/app/_layout.tsx`. `AppReadyGate` hides the splash on first layout after the DB `onInit`, MMKV preload, first-run cleanup and `hasApiKey` are done. `AppErrorBoundary` also hides it so startup errors are visible.
- Provider order: GestureHandlerRootView → Redux → QueryClientProvider → PaperProvider → SQLiteProvider → AppReadyGate.
- **Bootstrap timeout and `hasApiKey` (requirement for the API-key Settings feature; not implemented yet):** a `hasApiKey = false` set because `BOOTSTRAP_TIMEOUT_MS` elapsed (`src/hooks/useAppBootstrap.ts`) is **provisional**. A late bootstrap result must never overwrite a newer `setHasApiKey` dispatched meanwhile (latest write wins). Saving/removing the key must wait for, or supersede, any in-flight first-run cleanup, or a late `deleteItemAsync` can delete the freshly saved key. The chat-entry prompt must not set the persisted `ai_chat_prompt_shown` from a timed-out `false`.

### Performance
- No synchronous DB work at import time. QueryClient is created once at module scope.
- FlashList v2 (no `estimatedItemSize`) instead of FlatList; `expo-image` instead of `<Image>`; Reanimated worklets for animation; heavy work off the JS thread.
- Every listener/interval/subscription hook cleans up on unmount.
- **Callback refs** (especially inside `.map()` or components that re-render) must have a stable identity, or must not treat `null` as unmount: a ref whose identity changes is detached and re-attached on every render. Do cleanup via the React 19 ref cleanup function (return it from the callback) or an effect. Example: `useNoteField` (`useCallback` with no deps, latest callback read through a ref synced in `useLayoutEffect`), so `onFieldBlur` fires only on a real blur or unmount.

### Tests
- Jest via `jest-expo`; tests in `src/tests/__tests__/`, mocks in `src/tests/__mocks__/`, helpers in `src/tests/helpers/`. `roots` is `src/` so Jest picks up the package mocks in `src/tests/__mocks__/` automatically (root-level `__mocks__` must sit in a root); `collectCoverageFrom` is what makes untested source files count in coverage. `testMatch` limits tests to `src/tests/__tests__/`.
- **Coverage thresholds (D32):** lines 65, statements 65, functions 65, branches 50. Only these are excluded: `src/services/notifications/`, `src/services/anthropic/`, `src/ui/screens/ChatScreen/`, `src/state/chatSlice`, `src/app/chat.tsx` (plus `src/types/`, `src/tests/`). Don't add exclusions to hit the numbers.
- MMKV 4 returns its own in-memory mock under Jest; `react-native-nitro-modules` needs the stub in `src/tests/__mocks__/`. SecureStore is an in-memory mock: get it with `secureStoreMock()` (not `jest.requireMock`, which returns a different instance).
- RNTL 14: `render`, `renderHook` and `fireEvent` are async — always `await` them. expo-router's `renderRouter` helpers (`getPathname` …) sit on the returned Promise; see `src/tests/__tests__/app/navigation.test.tsx`.
- Real SQLite in tests via `NodeSqliteAdapter` (`node:sqlite`, Node ≥ 22.13). It opens connections with foreign keys **off** (`enableForeignKeyConstraints: false`), like expo-sqlite, so only `configureConnection`'s PRAGMA turns them on.
- Date tests must pass in any `TZ` (`yarn test:tz`).

### Done-gate
`yarn run check` passes before a task is declared done: `yarn lint`, `yarn typecheck`, `yarn test:coverage` (thresholds met) and `yarn test:tz`.
